# 在實機上開機（Lenovo ThinkStation P520 與其他 UEFI 電腦）

> P10 由自動排程一次做完，使用者已於 2026-10-21 審核。**只在 QEMU 驗證過，沒有在實機開過**——這份文件的目的就是把實機的結果帶回來。

## 1. 映像長什麼樣

`make disk-image` 產生 `build/stela.img`（`tools/make_disk_image.py`）：

```
LBA 0          protective MBR（類型 0xEE；沒有 STELATEST 測試標記）
LBA 1..33      GPT 標頭與分割區表
1 MiB          "EFI system"（FAT32，64 MiB）
                 EFI/BOOT/BOOTX64.EFI   STELA 的 loader（UEFI 的「可移除媒體」預設路徑）
                 STELA/kernel.elf
                 STELA/initrd.tar
                 STELA/boot.cfg         開機選項（§3），預設全部註解掉
                 STELA/slot             用哪一槽的 System（P14 K5，`docs/system.md` §4）
65 MiB         "System A"（STELA System 類型，SYSTEM_MIB= 預設 64 MiB）：build/system.img（P14）
129 MiB        "System B"：空的（更新寫在這裡）
193 MiB        "Data"（eHFS，預設 4096 MiB，DATA_MIB= 可改）：Welcome.txt
                 Classic/ROM、Classic/System.img   本機有你的 Mac 檔案時才有（P11 K30）
結尾 - 33      備份的分割區表與標頭
```

- **Classic 環境的檔案（P11 K30，使用者已於 2026-10-22 審核）**：`MAC_ROM`、`MAC_DISK`（預設 `~/mac/` 裡的 IIci ROM 與 `System7_5_3.img`，和 `make test-classic` 一樣）都存在時，`make disk-image` 用 `ehfs-cp` 把它們**複製**進映像的 `Data:/Classic/ROM`、`Data:/Classic/System.img`（`~/mac/` 只讀；只寫 `build/stela.img`），印 `disk-image: copied your Mac ROM and System disk …`。沒有就印一行說明、照樣做映像（Classic.app 會說缺什麼）。**這樣做出來的映像含有 Apple 的檔案，只能你自己用，不要分享**；不想放進去：`make disk-image MAC_ROM=`。`classic.cfg` 沒有放（預設值；要改設定在 STELA 裡寫 `Data:/Classic/classic.cfg`，`docs/classic.md` §9）。

- 映像是稀疏檔：`ls -ls` 看得到實際只佔幾 MB。寫進隨身碟後，隨身碟至少要 4.1 GB（`make disk-image DATA_MIB=1024` 可以做小一點的）。
- 腳本只寫 `build/` 底下的一般檔案；mtools 用 `-i` 對映像檔操作，`mkfs.ehfs`／`ehfs-cp` 也只接受一般檔案。**寫進隨身碟是你自己的步驟**（§2）。
- 沒有測試標記，所以 selftest 不會對這顆磁碟寫原始區塊；一般的 kernel 會把 ESP 掛成唯讀的 `Boot`、eHFS 掛成可寫的 `Data`。
- **注意**：kernel 會把它看到的**任何** GPT 磁碟上的 eHFS 分割區掛成可寫（`docs/vfs.md`）。P520 的其他磁碟（NVMe、SATA）沒有 eHFS，所以不會被寫，但保險起見測試期間可以拔掉資料碟。

想先在 QEMU 試一樣的映像：`make test-disk-image`（Data 只有 128 MiB 的版本，當成 AHCI 磁碟開機兩次）。

## 2. 寫進隨身碟（你自己做）

**這會清掉整支隨身碟。寫錯裝置會毀掉那個裝置的資料。**

1. 先**不要**插隨身碟，列出現有的磁碟：

   ```bash
   lsblk -o NAME,SIZE,MODEL,TRAN,MOUNTPOINT
   ```

2. 插上隨身碟，再列一次。**多出來的那一個**（`TRAN` 是 `usb`，大小與隨身碟相符）就是它，例如 `sdb`。確定它不是系統碟（系統碟有 `/`、`/boot/efi` 之類的掛載點）。
3. 卸載它的分割區、寫入（把 `sdX` 換成上一步的名稱；是整顆磁碟 `sdb`，不是分割區 `sdb1`）：

   ```bash
   sudo umount /dev/sdX* 2>/dev/null
   sudo dd if=build/stela.img of=/dev/sdX bs=4M conv=fsync status=progress
   sync
   ```

   整個映像（約 4.1 GB）都會寫過去，USB 2.0 的隨身碟要幾分鐘。不要用 `conv=sparse`：eHFS 可能依賴映像裡全為 0 的區域。
4. 想改開機選項：寫完後重插，Ubuntu 會掛載 FAT 分割區（`STELA`），編輯 `STELA/boot.cfg` 後安全移除。

## 3. 開機選項：`STELA/boot.cfg`

loader 讀 ESP 的 `\STELA\boot.cfg`（沒有這個檔也可以）。每行一個選項，`key` 或 `key=value`，`#` 之後是註解。loader 把它們正規化成以空白分隔的一行（最多 256 bytes），放進 `BootInfo::cmdline`（版本 3，`docs/boot.md` §9），開機時印 `boot: options …`。kernel 用 `frame::boot_flag(key)` 查，使用者程式用 `SysInfo(CMDLINE)`（libstela `process::boot_flag`）。

| 選項 | 效果 | 誰看 |
|---|---|---|
| `textmode` | 不啟動視窗伺服器：開機畫面立刻換成文字主控台，init 直接啟動 shell（`init: text mode (boot option)`） | init、kernel |
| `nowindow` | 同 `textmode` | init、kernel |
| `nousb` | 不啟動 xHCI 驅動（`usb: off (boot option nousb)`）；USB 鍵盤要靠韌體的 PS/2 模擬 | kernel |
| `nosmp` | 只用第一顆處理器（P10 的 SMP 完成後生效，`docs/smp.md`） | kernel |
| `idle=hlt`／`idle=mwait` | 閒置時用 `hlt`，或只要有 MONITOR 就用 `mwait`（P14；預設依 CPUID 決定，`docs/smp.md` §6.1） | frame |
| `nonet` | 不啟動網路（`net: off (boot option nonet)`；`docs/net.md`） | kernel |
| `verbose` | 開機的每個步驟前後各印一行（`boot: PCI ...`、`boot: PCI done (1.234 ms)`），畫面與 serial 都有；不畫開機畫面，訊息留在螢幕上（P11 K29，§3.1） | frame、kernel |
| `waitkey` | 每個步驟之後停下來印 `boot: press any key (5 s)`，等一個按鍵（沒有鍵盤時 5 秒後繼續）；搭配 `verbose` 一步一步看（P11 K29） | frame、kernel |
| `system=a`、`system=b`、`system=auto` | P14 K5：用哪一槽的 System 卷宗；`auto`（預設）照 ESP 的 `STELA/slot`（`docs/system.md` §4）；指定的槽壞了仍會換另一槽並印警告；指定時不改 slot 檔 | kernel |
| `verify` | P14 K5：每次開機都把 System 映像整個算一次 SHA-256（平常只在更新後第一次、或上次沒有開到桌面時算） | kernel |
| `imecrash` | 測試用（P14 K1，`make test-ime`）：輸入法一啟動就結束，檢查視窗伺服器的重啟 | ime |
| `serial`、`classic=off` | 保留，目前沒有作用（序列埠一律開著） | — |

值 `off`、`0`、`no` 等於沒有設（`nousb=off`）；同一個選項出現兩次以後面的為準；大小寫不分。

除錯建議：桌面起不來 → 試 `textmode`（**注意**：文字模式永遠不會呼叫 `BootOk`，開兩次後 kernel 會自動換到另一個 System 槽——用 `textmode` 除錯時一起寫 `system=a`（或 `b`），指定槽時不計次；`docs/system.md` §4）；鍵盤沒反應或開機卡在 USB → 試 `nousb`；開機卡在網卡（I219）→ 試 `nonet`；多核心時當掉 → 試 `nosmp`。開機卡住但不知道卡在哪 → 加 `verbose`（最後一行 `boot: X ...` 沒有 `done` 的就是 X），還看不清楚再加 `waitkey`。

### 3.1 開機診斷（P11 K29，使用者已於 2026-10-22 審核）

**比喻**：實機開機卡住時，畫面上只有石碑，不知道卡在哪一關。`verbose` 像是在每一關門口簽到、出來再簽退；`waitkey` 則是每過一關就停下來等你點頭。

- **步驟**（`frame::console::step(name, f)`）：frame 裡的 `cpu tables (GDT, TSS, IDT)`、`PAT`、`memory`、`screen`、`ACPI`、`interrupt controllers`、`per-CPU area`、`keyboard and mouse (PS/2)`、`timer`；kernel 的 `scheduler`、`other processors`、`PCI`、`disks`、`USB`、`sound`、`network`、`volumes`。`screen` 之前的訊息只到 serial（framebuffer 主控台還沒有）；`timer` 之前花的時間都是 0（還沒有時鐘）。
- **`waitkey`** 只在 frame 初始化完（中斷、計時器、PS/2 都好了）之後才等，也就是 kernel 的那 8 步；PS/2 鍵盤立刻有用，USB 鍵盤要等 `USB` 那步之後它的執行緒跑起來（之前的步驟會等滿 5 秒）。
- **訊息留在畫面上**：`textmode` 或 `verbose` 時不畫開機畫面（石碑），文字主控台從頭開著，結束時也不清掉；`textmode` 時 shell 接在開機訊息後面。
- **panic 畫面的最後 10 行**：主控台另外記著最後 16 行 kernel 訊息（`frame::console::ring::LineRing`：固定大小、不配置記憶體，每行最多 120 bytes；純邏輯，host 測試），panic 畫面在底部用較暗的字畫出最後 10 行（`last kernel messages:`），所以就算沒有 serial，也看得到 panic 前發生什麼。訊息太多、擺不下時不畫。


## 4. BIOS 設定與開機選單（P520 的 Lenovo BIOS）

- 開機時按 **F1** 進 Setup：Startup → Boot Mode = **UEFI Only**；**Secure Boot 關閉**（Security → Secure Boot → Disabled；STELA 的 loader 沒有簽章）；CSM 關閉（STELA 只支援 UEFI）。
- 開機時按 **F12** 叫出開機選單，選隨身碟的 UEFI 項目（名稱通常是 `USB HDD: …` 或 `UEFI: …`）。
- 不需要動 Above 4G Decoding、x2APIC（kernel 用 xAPIC）。

## 5. 看到什麼算成功

| # | 項目 | 成功的樣子 | 請回報 |
|---|---|---|---|
| 1 | loader | 黑底白字 `STELA boot loader 0.1.0`、`boot: kernel at …`、`boot: framebuffer WxH …`（一閃而過） | 若停在這裡：最後一行的照片 |
| 2 | 開機畫面 | 石碑出現在畫面中央 | 解析度是否與螢幕相符（loader 選面積最大的橫向模式） |
| 3 | 桌面 | 選單列、右邊的卷宗圖示（Boot、Data、Initrd、Tmp）、一個 terminal 視窗裡有 `STELA shell` | 照片 |
| 4 | 鍵盤與滑鼠 | 在 terminal 打 `help`、`vols`、`mem`；移動滑鼠、雙擊 Data | 哪個沒反應；改試 `nousb`（§3） |
| 5 | Data 可寫 | `mkdir test`、`ls Data:/`；`shutdown` 後再開機，`test` 還在 | — |
| 6 | 關機 | shell 打 `shutdown` | 電腦關機；若停住，畫面最後的訊息 |

P520 沒有傳統的序列埠（UART 是 Intel LPSS 的 MMIO），所以 serial 的開機訊息在實機上看不到，只能靠畫面。

## 6. 失敗時

- **panic**：畫面是裂開的石碑與訊息（`docs/identity.md`）。拍下整個畫面，訊息裡有檔名與行號。
- **黑畫面、停住**：拍最後的畫面；改試 `textmode`，再試 `nousb`，告訴 Claude 哪個組合可以。
- **重開機迴圈**（triple fault）：多半是很早期的錯；拍 loader 的最後幾行（可以在 F12 選單後馬上用手機錄影）。
- **找不到開機項目**：確認 Secure Boot 關閉、Boot Mode 是 UEFI；隨身碟的 ESP 是 FAT32、路徑是 `EFI/BOOT/BOOTX64.EFI`（Ubuntu 上 `ls` 掛載點確認）。

## 6.5 硬體相容清單（P12，使用者已於 2026-10-22 審核）

Lenovo ThinkStation P520 的硬體與 STELA 的支援。「QEMU 驗證」= 同一種（或同一家族的）裝置在 `make test` 的 QEMU 上跑過；「實機待驗」= 還沒在 P520 上開過機。PCI 的 vendor:device 與位置來自 P12 計畫（使用者提供的這台機器的資料）。

| 裝置 | ID | 位置 | STELA | 狀態 |
|---|---|---|---|---|
| CPU：Xeon W-2135（6 核 12 緒） | — | — | x86-64、SSE2；RDSEED（`frame::random`）、invariant TSC、x2APIC 只用 xAPIC 模式；SMP 最多 16 顆 | QEMU（TCG）驗證；實機待驗 |
| 晶片組 C422：I/O APIC | 8086:2026 | bus 0 | 中斷繞送（MADT） | QEMU（q35 的 I/O APIC）驗證；實機待驗 |
| xHCI USB 3.0 | 8086:a2af | bus 0；**BAR 在 4 GiB 以上** | `drivers/usb/xhci.rs`：鍵盤、滑鼠、hub、隨身碟（Bulk-Only） | QEMU（qemu-xhci）驗證；實機待驗（64 位元 BAR 已支援） |
| NVMe：Kingston KC3000 | 2646:5013 | **bus 0x17**（不在橋後面） | `drivers/nvme.rs` | QEMU（nvme）驗證；實機待驗；P12 起 PCI 掃描全部 256 個 bus，所以找得到 |
| SATA AHCI | 8086:a282 | bus 0 | `drivers/ahci.rs` | QEMU（ich9-ahci）驗證；實機待驗 |
| 網路：Intel I219-LM | 8086:15b7 | bus 0 | `drivers/net/e1000.rs`（e1000e／I219 路徑） | QEMU（e1000e）驗證；I219 實機待驗 |
| 音效：HDA | 8086:a2f0 | bus 0；**BAR 在 4 GiB 以上** | `drivers/hda.rs`（輸出、48 kHz） | QEMU（intel-hda + hda-duplex）驗證；codec 實機待驗 |
| 顯示：GeForce GTX 1070 | 10de:1b81 | **bus 0x65**（不在橋後面） | 只用 UEFI GOP 的 framebuffer（原生驅動：可選，之後） | QEMU（OVMF 的 GOP）驗證；實機待驗 |
| 鍵盤／滑鼠（韌體的 PS/2 模擬） | — | i8042 | `frame::input`；USB 出問題時 `boot.cfg` 的 `nousb` 退回 PS/2 模擬 | QEMU 驗證；實機待驗 |

- 測試的方式見 §5、§6；實機上看到的 `hwinfo` 輸出貼進這張表（之後由使用者做）。
- P12 的 PCI 改動：原本從 bus 0 沿著 PCI-to-PCI 橋遞迴找；P520 的 NVMe（bus 0x17）與 GTX（bus 0x65）在不同的根匯流排上（由晶片組的根 complex 直接接出，不在橋後面），遞迴找不到。現在遞迴找完之後再把 0–255 每一個還沒看過的 bus 都掃一次（`visited` 避免重複；`drivers/src/pci/mod.rs`，host 測試：bus 0x17 上一個沒有橋指向的裝置也找得到）。

## 8. 計畫外的決定與限制

- ESP 固定 64 MiB；P14 起後面是兩個 System 槽（各 `SYSTEM_MIB`），Data 從 65 + 2 × 64 = 193 MiB 開始（`DATA_SECTOR` 395264），結尾留 33 個磁區給備份 GPT。
- `serial`、`classic=off` 目前只是保留名稱。
- `boot.cfg` 的選項不經過 UEFI 變數，也不能在開機選單裡臨時改；要改就編輯 ESP 上的檔案。
