# 在實機上開機（Lenovo ThinkStation P520 與其他 UEFI 電腦）

> P10 由自動排程一次做完，**使用者尚未審核**；之後修改前請先帶使用者過一遍這份文件。**只在 QEMU 驗證過，沒有在實機開過**——這份文件的目的就是把實機的結果帶回來。

## 1. 映像長什麼樣

`make disk-image` 產生 `build/stela.img`（`tools/make_disk_image.py`）：

```
LBA 0          protective MBR（類型 0xEE；沒有 STELATEST 測試標記）
LBA 1..33      GPT 標頭與分割區表
1 MiB          "EFI system"（FAT32，64 MiB）
                 EFI/BOOT/BOOTX64.EFI   STELA 的 loader（UEFI 的「可移除媒體」預設路徑）
                 STELA/kernel.elf
                 STELA/initrd.tar
                 STELA/boot.cfg         開機選項（§3），預設全部註解掉
65 MiB         "Data"（eHFS，預設 4096 MiB，DATA_MIB= 可改）：Welcome.txt
結尾 - 33      備份的分割區表與標頭
```

- 映像是稀疏檔：`ls -ls` 看得到實際只佔幾 MB。寫進隨身碟後，隨身碟至少要 4.1 GB（`make disk-image DATA_MIB=1024` 可以做小一點的）。
- 腳本只寫 `build/` 底下的一般檔案；mtools 用 `-i` 對映像檔操作，`mkfs.ehfs`／`ehfs-cp` 也只接受一般檔案。**寫進隨身碟是你自己的步驟**（§2）。
- 沒有測試標記，所以 selftest 不會對這顆磁碟寫原始區塊；一般的 kernel 會把 ESP 掛成唯讀的 `Boot`、eHFS 掛成可寫的 `Data`。
- **注意**：kernel 會把它看到的**任何** GPT 磁碟上的 eHFS 分割區掛成可寫（`docs/vfs.md`）。P520 的其他磁碟（NVMe、SATA）沒有 eHFS，所以不會被寫，但保險起見測試期間可以拔掉資料碟。

想先在 QEMU 試一樣的映像：`make test-disk-image`（Data 只有 128 MiB 的版本，當成 AHCI 磁碟開機兩次）。

## 2. 寫進隨身碟（你自己做）

**這會清掉整支隨身碟。寫錯裝置會毀掉那個裝置的資料。**

1. 先**不要**插隨身碟，列出現有的磁碟：

   ```bash
   lsblk -o NAME,SIZE,MODEL,TRAN,MOUNTPOINT
   ```

2. 插上隨身碟，再列一次。**多出來的那一個**（`TRAN` 是 `usb`，大小與隨身碟相符）就是它，例如 `sdb`。確定它不是系統碟（系統碟有 `/`、`/boot/efi` 之類的掛載點）。
3. 卸載它的分割區、寫入（把 `sdX` 換成上一步的名稱；是整顆磁碟 `sdb`，不是分割區 `sdb1`）：

   ```bash
   sudo umount /dev/sdX* 2>/dev/null
   sudo dd if=build/stela.img of=/dev/sdX bs=4M conv=fsync status=progress
   sync
   ```

   整個映像（約 4.1 GB）都會寫過去，USB 2.0 的隨身碟要幾分鐘。不要用 `conv=sparse`：eHFS 可能依賴映像裡全為 0 的區域。
4. 想改開機選項：寫完後重插，Ubuntu 會掛載 FAT 分割區（`STELA`），編輯 `STELA/boot.cfg` 後安全移除。

## 3. 開機選項：`STELA/boot.cfg`

loader 讀 ESP 的 `\STELA\boot.cfg`（沒有這個檔也可以）。每行一個選項，`key` 或 `key=value`，`#` 之後是註解。loader 把它們正規化成以空白分隔的一行（最多 256 bytes），放進 `BootInfo::cmdline`（版本 3，`docs/boot.md` §9），開機時印 `boot: options …`。kernel 用 `frame::boot_flag(key)` 查，使用者程式用 `SysInfo(CMDLINE)`（libstela `process::boot_flag`）。

| 選項 | 效果 | 誰看 |
|---|---|---|
| `textmode` | 不啟動視窗伺服器：開機畫面立刻換成文字主控台，init 直接啟動 shell（`init: text mode (boot option)`） | init、kernel |
| `nowindow` | 同 `textmode` | init、kernel |
| `nousb` | 不啟動 xHCI 驅動（`usb: off (boot option nousb)`）；USB 鍵盤要靠韌體的 PS/2 模擬 | kernel |
| `nosmp` | 只用第一顆處理器（P10 的 SMP 完成後生效，`docs/smp.md`） | kernel |
| `nonet` | 不啟動網路（`net: off (boot option nonet)`；`docs/net.md`） | kernel |
| `serial`、`classic=off` | 保留，目前沒有作用（序列埠一律開著） | — |

值 `off`、`0`、`no` 等於沒有設（`nousb=off`）；同一個選項出現兩次以後面的為準；大小寫不分。

除錯建議：桌面起不來 → 試 `textmode`；鍵盤沒反應或開機卡在 USB → 試 `nousb`；開機卡在網卡（I219）→ 試 `nonet`；多核心時當掉 → 試 `nosmp`。

## 4. BIOS 設定與開機選單（P520 的 Lenovo BIOS）

- 開機時按 **F1** 進 Setup：Startup → Boot Mode = **UEFI Only**；**Secure Boot 關閉**（Security → Secure Boot → Disabled；STELA 的 loader 沒有簽章）；CSM 關閉（STELA 只支援 UEFI）。
- 開機時按 **F12** 叫出開機選單，選隨身碟的 UEFI 項目（名稱通常是 `USB HDD: …` 或 `UEFI: …`）。
- 不需要動 Above 4G Decoding、x2APIC（kernel 用 xAPIC）。

## 5. 看到什麼算成功

| # | 項目 | 成功的樣子 | 請回報 |
|---|---|---|---|
| 1 | loader | 黑底白字 `STELA boot loader 0.1.0`、`boot: kernel at …`、`boot: framebuffer WxH …`（一閃而過） | 若停在這裡：最後一行的照片 |
| 2 | 開機畫面 | 石碑出現在畫面中央 | 解析度是否與螢幕相符（loader 選面積最大的橫向模式） |
| 3 | 桌面 | 選單列、右邊的卷宗圖示（Boot、Data、Initrd、Tmp）、一個 terminal 視窗裡有 `STELA shell` | 照片 |
| 4 | 鍵盤與滑鼠 | 在 terminal 打 `help`、`vols`、`mem`；移動滑鼠、雙擊 Data | 哪個沒反應；改試 `nousb`（§3） |
| 5 | Data 可寫 | `mkdir test`、`ls Data:/`；`shutdown` 後再開機，`test` 還在 | — |
| 6 | 關機 | shell 打 `shutdown` | 電腦關機；若停住，畫面最後的訊息 |

P520 沒有傳統的序列埠（UART 是 Intel LPSS 的 MMIO），所以 serial 的開機訊息在實機上看不到，只能靠畫面。

## 6. 失敗時

- **panic**：畫面是裂開的石碑與訊息（`docs/identity.md`）。拍下整個畫面，訊息裡有檔名與行號。
- **黑畫面、停住**：拍最後的畫面；改試 `textmode`，再試 `nousb`，告訴 Claude 哪個組合可以。
- **重開機迴圈**（triple fault）：多半是很早期的錯；拍 loader 的最後幾行（可以在 F12 選單後馬上用手機錄影）。
- **找不到開機項目**：確認 Secure Boot 關閉、Boot Mode 是 UEFI；隨身碟的 ESP 是 FAT32、路徑是 `EFI/BOOT/BOOTX64.EFI`（Ubuntu 上 `ls` 掛載點確認）。

## 7. 測試

| 測試 | 內容 |
|---|---|
| host `bootinfo` | 版本 3 的位移、`parse_config`（註解、空白、CRLF、非 ASCII、放不下） |
| host `abi` | `cmdline_option`／`cmdline_flag`（大小寫、`off`、後面的為準） |
| `make test-qemu` | `make esp-test` 放一個 `boot.cfg`（`selftest`）：selftest 檢查 `boot_flag("selftest")` 與 AP trampoline 頁（640 KiB 以下、頁對齊） |
| `make test-textmode` | 一般 kernel、`boot.cfg` = `textmode` + `nousb`（含註解與空白）、接 `qemu-xhci`：`usb: off`、`init: text mode`、shell 回應 `uptime` |
| `make test-disk-image` | `make_disk_image.py` 做 Data 128 MiB 的映像，當成唯一的 AHCI 磁碟開機（OVMF 從它的 ESP 開機）：桌面起來、shell `mkdir` 後 `shutdown`；host 的 `fsck.ehfs` 確認正常卸載、`ehfs-ls` 看到資料夾；第二次開機 `ls Data:/` 看到它與 `Welcome.txt` |

## 8. 計畫外的決定與限制

- ESP 固定 64 MiB；Data 從 65 MiB 開始，結尾留 33 個磁區給備份 GPT。
- `serial`、`classic=off` 目前只是保留名稱。
- `boot.cfg` 的選項不經過 UEFI 變數，也不能在開機選單裡臨時改；要改就編輯 ESP 上的檔案。
